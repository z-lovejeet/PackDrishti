# PackDrashiti (SIH26034) - RESTful API Contract Specification

- **Project Name**: PackDrashiti
- **Problem Statement ID**: SIH26034
- **Document Version**: 1.0.0
- **Base URL**: `/api/v1`
- **Default Media Type**: `application/json`
- **Security Scheme**: RFC 6750 Bearer Token (JSON Web Token - JWT)
- **Target Systems**: React 19 Frontend Web & Mobile Client, Python FastAPI Gateway & Backend Services, Multimodal VLM / PaddleOCR / Statutory RAG AI Pipeline Workers, PostgreSQL Relational Database, MinIO / S3 Storage Subsystem

---

## 1. Document Overview and Scope

This document provides the exhaustive, formal RESTful API contract for Project PackDrashiti (SIH26034). PackDrashiti automates legal metrology enforcement under the Legal Metrology Act, 2009 and the Legal Metrology (Packaged Commodities) Rules, 2011, alongside food safety and nutritional compliance under Food Safety and Standards Authority of India (FSSAI) guidelines and ICMR-NIN (Indian Council of Medical Research - National Institute of Nutrition) dietary benchmarks.

The API defined herein forms the binding architectural contract between:
- **Client Tier**: Web dashboard and mobile field inspection application.
- **Application Tier**: Python FastAPI asynchronous application server.
- **AI Processing Pipeline**: High-throughput distributed inference workers executing Multimodal VLM (Gemini 1.5 Flash / GPT-4o-mini) and PaddleOCR spatial extraction, deterministic Python rule verification, calibrated pixel-to-millimeter physical measurement models, and pgvector statutory RAG retrieval.
- **Persistence Tier**: Relational PostgreSQL database and S3-compatible document/image storage.

All endpoints strictly mandate the JSON data interchange format for structured payloads, multipart form encodings for raw binary file uploads, and standard binary streams for statutory PDF downloads.

## 2. Global Conventions, Headers, and Envelope Schemas

### 2.1 Base Path and Protocol Standards
- **Protocol**: HTTPS / TLS 1.3 mandatory in production.
- **Base URL**: `/api/v1`
- **Character Encoding**: UTF-8 throughout all request and response streams.
- **Date/Time Standard**: ISO 8601 extended UTC format: `YYYY-MM-DDTHH:mm:ss.sssZ` (example: `2026-09-10T12:00:00.000Z`).
- **Monetary Values**: Decimal representation in Indian Rupee (INR) up to two decimal places (e.g., `25000.00`).
- **Physical Metrics**: Packaging surface area in square centimeters (`cm2`), font dimensions in millimeters (`mm`), and weights in standard metric units (`g`, `kg`, `ml`, `l`).

### 2.2 Global Request Headers

| Header | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `Authorization` | String | Conditional | Format: `Bearer <jwt_token>`. Mandatory for all protected endpoints. |
| `Content-Type` | String | Conditional | `application/json` for structured requests; `multipart/form-data` for file uploads. |
| `Accept` | String | Yes | Client expects `application/json` (or `application/pdf` for file downloads). |
| `X-Request-ID` | String (UUID) | Optional | Distributed tracing UUID. Generated by gateway if omitted. |
| `X-Client-Version` | String | Optional | Client build identifier (e.g., `PackDrashiti-Web/1.0.0`, `PackDrashiti-Android/1.2.0`). |
| `X-Device-ID` | String | Optional | Hardware or installation UUID for audit trail verification in field enforcement. |

### 2.3 Global Response Headers

| Header | Type | Description |
| :--- | :--- | :--- |
| `X-Request-ID` | String (UUID) | Echoed or server-generated correlation identifier for distributed tracing. |
| `X-Response-Time-MS` | Float | Server execution latency in milliseconds from gateway ingress to egress. |
| `RateLimit-Limit` | Integer | Maximum permissible request count within current rolling window. |
| `RateLimit-Remaining` | Integer | Remaining request allotment within current window. |
| `RateLimit-Reset` | Integer | Epoch timestamp (in seconds) when the rate limit window refreshes. |

### 2.4 Standard Error Response Envelope
All non-2xx HTTP responses follow a strict, uniform JSON envelope.

```json
{
  "status": "error",
  "error_code": "VALIDATION_ERROR",
  "message": "The request payload failed structural validation checks.",
  "details": [
    {
      "field": "pdp_area_cm2",
      "issue": "Field must be a positive float greater than 0.0."
    }
  ],
  "timestamp": "2026-09-10T12:45:00.000Z",
  "request_id": "b3f8ebbf-f6aa-4f97-8fa5-7cff188a7043"
}
```

#### Envelope Attributes:
- `status` (string, constant: `"error"`): Explicit discriminator flag.
- `error_code` (string, uppercase snake_case): Unique machine-readable error token defined in Section 8.
- `message` (string): Concise human-readable summary of the error condition.
- `details` (array of objects, optional): Field-level validation violations or underlying pipeline diagnostic messages.
- `timestamp` (string, ISO 8601): Exact server time at which the error occurred.
- `request_id` (string, UUID): Diagnostic trace identifier.

### 2.5 Standard Pagination Specification
Endpoints returning collections support deterministic pagination, sorting, and field filtering.

#### Standard Query Parameters:

| Parameter | Type | Default | Validation | Description |
| :--- | :--- | :--- | :--- | :--- |
| `page` | Integer | `1` | `page >= 1` | 1-based page index. |
| `limit` | Integer | `20` | `1 <= limit <= 100` | Number of records per page. |
| `sort_by` | String | `created_at` | Valid field name | Target entity column for sorting. |
| `sort_order` | String | `desc` | `asc`, `desc` | Sort direction. |

#### Paginated Response Envelope:

## 3. Authentication & Access Control Endpoints (`/api/v1/auth`)

### 3.1 User Registration
Registers a new user account. Supports consumer citizen signups and government enforcement officer registrations with verification credentials.

- **Path**: `POST /api/v1/auth/register`
- **Authentication**: None (Public Endpoint)
- **Request Content-Type**: `application/json`

#### Request Body Schema:

| Field | Type | Required | Constraints | Description |
| :--- | :--- | :--- | :--- | :--- |
| `email` | String | Yes | Valid email, max 255 chars | User official or personal email address. |
| `password` | String | Yes | Min 8 chars, 1 uppercase, 1 lowercase, 1 number, 1 special char | Plaintext account password. |
| `full_name` | String | Yes | Min 2, max 100 chars | Legal full name of user. |
| `role` | String | Yes | Enum: `consumer`, `officer`, `auditor`, `admin` | Authorization role profile. |
| `badge_number` | String | Conditional | Max 50 chars; Required if role is `officer` | Official inspector badge identification code. |
| `designation` | String | Conditional | Max 100 chars; Required if role is `officer` | Government post or administrative title. |
| `zone` | String | Conditional | Max 100 chars | Assigned enforcement jurisdiction or zone. |
| `phone_number` | String | Optional | E.164 format (e.g., `+919876543210`) | Primary contact number. |

#### Request Example:
```json
{
  "email": "inspector.gupta@gov.in",
```

- **Authentication**: Optional (Supports anonymous consumer checks and authenticated profiles)
- **Request Content-Type**: `multipart/form-data`

#### Multipart Form Parameters:

## 10. Security, Rate Limiting & Verification Checklists

### 10.1 Authentication & Token Lifecycles
1. **Access Token Lifespan**: Signed JWTs have an expiration of 86,400 seconds (24 hours).
2. **Key Rotation & Algorithm**: Backend signs tokens exclusively using HMAC-SHA256 (`HS256`) with environment-injected secret keys (minimum 256 bits).
3. **Role-Based Authorization**: Protected endpoints require specific roles. Officers access enforcement routes, while consumers are restricted to personal scan and health checks.

### 10.2 Rate Limiting Rules
- **Authentication Routes** (`/api/v1/auth/login`, `/api/v1/auth/register`):
  - 10 requests per minute per IP address.
  - Exceeding quota returns HTTP `429 Too Many Requests` with header `Retry-After: 60`.
- **Scanning & AI Pipeline Routes** (`/api/v1/scan/upload`, `/api/v1/health/analyze`):
  - Consumer tier: 30 requests per hour.
  - Officer tier: 300 requests per hour.
- **Reporting & General Read Routes**:
  - 600 requests per hour.

### 10.3 File Upload Security & Sanitization
1. **Magic Byte Verification**: File payloads are inspected via binary headers to verify `image/jpeg`, `image/png`, or `image/webp`. Simple file extension matching is rejected.
2. **Size Enforcement**: Hard limit of 15 MB enforced at reverse proxy and application gateway layers.
3. **EXIF Metadata Stripping**: Scanned images undergo automatic EXIF metadata stripping to protect officer GPS privacy before persistent archival in public S3 buckets.
